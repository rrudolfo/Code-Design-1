CSS Resets

What browser inconsistencies bothered developers enough to create this?

  • Browsers used different default spacing for elements like headings, paragraphs, and lists, so pages did not look the same everywhere.
  • Lists were especially annoying because some browsers used margin for indentation, while others used padding.
  • Developers wanted a cleaner, more predictable starting point instead of fighting each browser’s built-in styles.

What changed between 2007 and now?

  • Modern browsers are much more consistent now, so resets do not need to be as heavy as older ones.
  • CSS has newer common fixes now, like box-sizing: border-box, responsive media defaults, and better form styling.
  • Modern resets are less about removing everything and more about creating a useful starting point.

Why does Josh modify or reject parts of Meyer’s approach?

  • Josh does not want a total blank slate; some browser defaults, like italic <em> text, are still useful.
  • Meyer’s reset is more aggressive, while Josh’s reset focuses on modern issues like image overflow, font inheritance, and readability.
  • Josh wants developers to understand and customize their reset instead of copying one forever.

The Variety of Approaches: Aggressive Resets vs. Gentle Normalization

  • Aggressive resets remove most browser default styling so the developer starts from almost nothing. Meyer’s reset is a good example of this style.
  • Gentle normalization keeps useful browser defaults but fixes inconsistencies. Normalize.css is a good example of this approach.
  • Modern middle-ground resets keep consistency but also add useful defaults like box-sizing: border-box, better default fonts, and clearer documented choices.

Other Reset or Normalize Approaches Online

  • Normalize.css: a gentler alternative that preserves useful defaults while making elements render more consistently across browsers.
  • modern-normalize: a smaller, modern version focused on current browsers, with additions like box-sizing: border-box.
  • sanitize.css: includes normalize-style fixes, but also adds useful defaults and clearly documents which parts are normalizations versus opinions.

Why Reset at All? What Problem Does It Solve?

  • A reset gives you a more consistent starting point by reducing differences between browser default styles.
  • It prevents you from fighting unexpected built-in spacing, like default margins, padding, list indentation, and heading sizes.
  • It helps make your CSS more intentional because you choose the spacing, sizing, and layout instead of relying on browser defaults.

Why Josh’s Version Over Eric’s? Specific Differences

  • Josh keeps useful defaults. Eric’s reset is more aggressive and removes many default styles, while Josh keeps helpful browser defaults instead of making everything a blank slate.
  • Josh adds modern fixes. His reset includes things like box-sizing: border-box, responsive media handling, and better form font inheritance, which are more useful for modern CSS layouts.
  • Josh is less "wipe everything out." Eric’s reset focuses on reducing old browser inconsistencies, while Josh focuses more on improving the developer starting point without removing every style.

How Do You Actually Use These? Link Tag, Import, or Inline?

  • The best common method is to put the reset in its own CSS file, then link it before your main stylesheet.
<link rel="stylesheet" href="reset.css">
<link rel="stylesheet" href="style.css">
  • You can also import it at the top of your main CSS file, but this is usually less preferred than using a normal link tag.
@import url("reset.css");
  • You can paste the reset directly at the top of your main CSS file. This works well for small custom resets because you can edit it for your project.

What’s a CSS Boilerplate vs. a Reset?

  • A CSS reset removes or adjusts browser default styles so every browser starts from a more consistent base.
  • A CSS boilerplate is a larger starting template that may include a reset, basic layout rules, typography, variables, utility classes, and starter project styles.
  • Simple difference: a reset is the cleanup step; a boilerplate is the full starter kit for building a website.

Why Use a Boilerplate? When Does It Help or Hurt?

  • It helps because it saves time by giving you a ready-made starting structure, like reset rules, typography, layout defaults, variables, and common utility classes.
  • It helps keep projects more consistent, especially when working on larger websites or with a team.
  • It can hurt because it may add extra CSS you do not understand or need, which can make your site harder to debug and customize.

Why Is Normalize.css Different from Resets? Philosophy Shift

  • Traditional resets remove styles so the developer starts from a blank slate; Normalize.css preserves useful browser defaults instead of wiping everything out.
  • Normalize.css focuses on fixing inconsistencies between browsers, not removing every margin, font size, or default style.
  • The philosophy shifts from "delete the browser’s styling" to "make browser styling more consistent and usable."
